# Product Principles

> Os princípios fundamentais que orientam todas as decisões do Indexa.

Estes princípios existem para garantir que o produto permaneça consistente ao longo do tempo.

Sempre que surgir uma nova funcionalidade, pergunta ou ideia, ela deve ser comparada com estes princípios.

Se a ideia violar um ou mais princípios, ela deve ser revista antes de ser implementada.

---

# Princípio 1

## O conteúdo é o protagonista.

O usuário utiliza o Indexa para acompanhar suas obras.

Não para admirar a interface.

Toda decisão visual deve destacar primeiro:

• a capa

• o título

• o progresso

Todo o restante é secundário.

---

# Princípio 2

## Organização acima de quantidade.

Adicionar mais funcionalidades não torna o produto melhor.

Uma funcionalidade só existe se realmente melhorar a organização da biblioteca.

---

# Princípio 3

## Simplicidade vence complexidade.

Sempre escolher a solução mais simples.

Se duas soluções resolverem o mesmo problema, utilizar a que exige menos aprendizado.

---

# Princípio 4

## Cada tela possui apenas um objetivo.

Home

→ Retomar sua jornada.

Biblioteca

→ Encontrar obras.

Dashboard

→ Descobrir padrões.

Configurações

→ Ajustar preferências.

Nunca misturar objetivos.

---

# Princípio 5

## O usuário nunca deve preencher o que a API conhece.

Se uma informação pode ser obtida automaticamente:

Título

Ano

Autor

Diretor

Estúdio

Desenvolvedora

Sinopse

Gêneros

Capa

Temporadas

Episódios

Volumes

ISBN

Duração

Ela deve ser preenchida automaticamente.

O usuário apenas complementa informações pessoais.

---

# Princípio 6

## Ações frequentes devem exigir um clique.

Favoritar

Alterar status

Avaliar

Continuar progresso

Essas ações nunca devem ficar escondidas.

---

# Princípio 7

## Informações importantes permanecem visíveis.

Sempre visíveis:

Título

Status

Avaliação

Progresso

Categoria

Ano

Informações secundárias ficam recolhidas.

---

# Princípio 8

## A interface deve desaparecer.

O usuário nunca deve perceber esforço para utilizar o aplicativo.

Quanto menos ele pensar sobre a interface, melhor.

---

# Princípio 9

## Consistência acima de criatividade.

Um mesmo componente sempre funciona da mesma forma.

O usuário aprende apenas uma vez.

---

# Princípio 10

## Registrar deve ser prazeroso.

Adicionar uma obra deve levar poucos segundos.

Nunca parecer preencher um formulário.

---

# Princípio 11

## A biblioteca pertence ao usuário.

O Indexa organiza.

Quem constrói a biblioteca é o usuário.

Toda decisão deve respeitar esse sentimento de propriedade.

---

# Princípio 12

## O progresso conta uma história.

O objetivo não é apenas marcar episódios.

É preservar uma jornada.

---

# Princípio 13

## Dados técnicos nunca competem com informações emocionais.

O usuário quer lembrar:

onde parou

o que achou

quando assistiu

As informações técnicas ficam sempre em segundo plano.

---

# Princípio 14

## O aplicativo deve envelhecer bem.

O usuário poderá utilizar o Indexa durante muitos anos.

As decisões tomadas hoje devem continuar fazendo sentido daqui a cinco anos.

---

# Princípio 15

## Menos cliques. Menos rolagem. Menos distrações.

Todo fluxo deve ser avaliado com estas perguntas:

Posso remover um clique?

Posso remover uma rolagem?

Posso remover uma decisão?

Se sim, remova.

---

# Princípio 16

## Nada entra no produto sem um motivo claro.

Antes de implementar qualquer funcionalidade, responder:

Que problema ela resolve?

Qual benefício traz?

Ela fortalece a missão do Indexa?

Ela melhora a experiência?

Se a resposta for "não", ela não deve ser implementada.

---

# Frase Guia

"O Indexa existe para organizar histórias, não interfaces."

Toda decisão futura deve reforçar essa ideia.
